Approach

Engineering Philosophy

A few principles I've settled on after nine years of building and running distributed systems.

01

Design for failure, operate for clarity

Things break. Brokers drop, jobs stall, nodes run out of memory. I build systems that degrade gracefully and make their failures visible, instead of quietly hoping they won't.

02

Governance is a feature, not friction

When many teams share one platform, contracts, access control, and observability aren't overhead. They're the product. I'd rather build that in from the start than bolt it on later.

03

Cost is an architectural property

Efficiency is a design constraint, not a quarterly cleanup. Cost, latency, and reliability are decisions you make up front, because that's when they're still cheap to change.

04

Boring primitives, deliberately applied

I reach for proven tools and keep novelty off the critical path. The interesting complexity belongs in the problem I'm solving, not in the stack that has to hold up at 3 a.m.

National Health Data Platform & Azure Databricks Architecture

Thoughtworks • HPB Singapore

I ran the infrastructure side of Singapore's national health data platform, which serves ~500,000 citizens. The biggest change was moving to a hub-and-spoke Azure Databricks workspace topology, which removed cross-workspace compute redundancy and isolated sensitive healthcare workloads. I also tracked down memory and partition problems that were destabilizing the HDInsight Spark clusters.

Impact: Slashed cross-workspace compute spend by ~20%, reduced Spark job failure rate by ~40%, and yielded ~$8,000/month in direct Azure cloud savings.

Real-Time CDC Event Streaming (Kafka + Debezium)

Thoughtworks • Data Platform

Built and ran an event-driven Change Data Capture (CDC) pipeline on an HDInsight Kafka cluster with Debezium connectors. It picks up transactional changes from the source databases as they happen and pushes them to downstream analytics engines and data catalogs, without adding lock contention on the primary OLTP tables.

Impact: Handled ~2,000,000 CDC events/day with sub-second event propagation, supporting both continuous streaming and ~5 TB/day batch Spark pipelines.
